# Fit results

`python3 -I fit.py <opcode file>...` over every opcode file of the corpus,
200 vectors per file, groups of 6 or more, prefix counts pooled; exceptions
and repeated string instructions excluded. One set of global constants;
each form's schedule fitted by `fit.py`.

309 opcode files, 60479 vectors in fitted groups, 54182 exact (89.6%);
without the shifts by a count, 53475 of 54588 (98.0%).

A form here is one schedule for every vector of it, so the shifts by a
count (`C0`, `C1`, `D2`, `D3`), whose work grows a clock per bit, fit
poorly; the description gives them the count (`5 + count` before a
register shift, `3 + count` between a memory shift's read and write) and
reproduces 92 to 95% of them. The far CALL (`9A`) has its jump between
its pushes, an order the search does not reach (`schedule(5, access, 5,
jump, 0, access, 0)` reproduces 89%). INTO, ENTER above level 0 and ESC
are in the README's list; SALC's time depends on CF.
